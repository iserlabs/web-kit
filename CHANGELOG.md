## 0.11.0
- **`@iserlabs/web-kit/artist`: shows.** A show (`Show`: title, kind, venue, address, city, first and last day, opening reception, the works hanging, the gallery's page, one line in the artist's words, published or held back) is typed once in the studio. `showStatus(show, now, timeZone)` reads its dates as calendar days in the site's time zone (default `America/New_York`, `DEFAULT_TIME_ZONE`), never as UTC, with the last day inclusive and daylight saving handled by `Intl`. `noticeShow` picks the homepage line (the show on now, else the next one within 45 days, gone the day after close); `onView` names the show a work is hanging in. `cleanShow(body, catalog)` refuses an incomplete or impossible show and names every problem in plain words (real calendar dates, last day not before first, opening within the run, 24-hour times, every listed work in the catalog, an http or https gallery link). `sanitizeStoredShows` drops a stored show missing a required fact and keeps valid data in stored key order. `showJsonLd(show, site)` builds the `ExhibitionEvent` schema, joined to each work's own `@id`.
- **Calendar dates.** `cleanShow` and `sanitizeStoredShows` accept only exact zero-padded `YYYY-MM-DD` dates that exist on the calendar.
- **CV from shows.** `cvFromShows(shows, now, timeZone)` turns every published show that has opened into a CV line (title, venue, city, year and the gallery's page; the show's note is not copied), newest first (`solo` and `event` under solo exhibitions, `two-person` and `group` under group). `mergeCv(cv, lines)` adds them to the hand-entered CV in the same `Cv` shape; a line typed by hand wins over a show with the same year and title.
- **Press kit.** `pressKit({ works, cv, shows, statement, now, timeZone })` assembles the statement, the CV with its shows, every published work's record with its highest-resolution served image (`hi`, else `src`) and no master file, with a price only where the work is available (public or on request), and a price list that carries on-request prices for galleries and lists sold, reserved, not-for-sale and unrecorded works without a price. Galleries see on-request prices in the press kit. `generatePressToken`, `isPressToken` and `pressTokenMatches` make and check the unlisted press address's token (256 random bits, constant-time compare).
- **Studio store.** `createStudioStore` takes optional `showsKey` and `pressKey` and returns the overlay store plus `shows` (`readShows`, `writeShow`, `deleteShow`) and `press` (`readToken`, `writeToken`), each under its own Upstash key and each reading null when unconfigured. `createStudioStore` throws at construction when any two of `key`, `showsKey` and `pressKey` are equal. `StudioStore` itself is unchanged.
- **Handlers.** `showsHandler({ auth, store, catalog, onError })` serves GET, PUT and DELETE for shows with the same cookie check, body cap and 503 answers as `workHandler`; `showsHandler` validates every PUT with `cleanShow`, and a refused show answers 400 with its `problems`; any signed-in role may delete a show. A PUT whose body carries `create: true` answers 409 "A show with that name already exists." and writes nothing when that slug is already saved; without it a PUT still overwrites its own slug.
- **Error reporting.** `onError` on both handlers may be async (`void | Promise<void>`). It is awaited, capped by an optional `reportTimeoutMs` (default 2000) so a hung reporter never holds the response, and a reporter that throws or rejects never changes the answer.
- **Config.** `ArtistConfig` gains optional `artistName`, `timeZone`, `series`, `studio.showsKey` and `press.tokenKey`. A phase-1 config still satisfies it unchanged.
- **Show words.** `formatShowDates(show)` prints a show's run in plain words ("November 7 – December 5, 2026", the month or the year said once when both ends share it) and `formatOpening(opening)` the reception ("Saturday, November 7, 6 to 9 PM", on a 12-hour clock). Both print the calendar date as stored, so no time zone can move a day.
- **Exhibition schema.** `showJsonLd` states `eventAttendanceMode` (in person) and takes optional `artist` (printed as `performer`, joined by its `@id`) and `workImage` (each listed work's image, as `image`). It states no `eventStatus`.
- **Press kit order.** `pressKit` takes the statement as one string or as its paragraphs, and returns `statement` as a list of paragraphs, verbatim, blank ones dropped. Works and the price list come in `forDisplay` order (current, then earlier, then archived; available first within each), so archived work appears, last. `formatPriceLine(entry)` words one price list line ("$6,800 · on request", "Sold", "Available, not priced yet", "Availability not recorded yet").
- **Press link route.** `pressHandler({ auth, store, onError })` serves GET (the current token, or null) and POST (a new token, which retires the old link at once) with the same cookie check and 503 answers as the other handlers; every answer carrying a token is sent `Cache-Control: no-store`. `StudioErrorContext.method` gains `"POST"`.
- **Store timeout.** Every store call is abandoned after `timeoutMs` (default 4000) and fails with "store timed out after N ms": the request is aborted, and the call fails even when the fetch ignores the abort, so a store that never answers cannot hold a page until the platform's own limit. `createStudioStore` refuses a `timeoutMs` that is not a positive number.

## 0.10.0
- **`@iserlabs/web-kit/artist`**, new export: the parts of an artist's portfolio site that are the same on every artist's site, extracted from julianpotulicki.com with no change to what that site shows. Framework-free `.ts` with no React and no Next imports; every server handler takes a Web `Request` and returns a `Response`.
  - Record: the `Artwork` type (Carole 06 fields; `Artwork<S>` takes the site's own series ids), the label formatters, `isPurchasable`, `missingFields`, `isFullyDocumented`, and `catalogIds(slugs, prefix)` for stable numbering under the site's prefix.
  - Availability: `groupByAvailability`, `hasAvailabilityData`, `currentFirst`, `forDisplay`, each given the works.
  - CV: the CV types plus `cvSections`, `newestFirst`, `cvGaps`, `hasCvContent`, each given the site's CV.
  - Studio auth: `createStudioAuth({ cookieName, roles, secretEnv })`, signed role cookies over Web Crypto that fail closed. The cookie format is the one julianpotulicki.com already issues, so adopting the module logs nobody out. A non-positive or fractional `ttlSeconds` is rejected, and a cookie token outside `[A-Za-z0-9._-]` is refused.
  - Studio store: `createStudioStore({ key })`, per-work overlays over Upstash REST with plain `fetch`, plus `merge` and `mergeAll`. `cachedRead` passes a framework's fetch options (Next's `revalidate`) through without importing the framework. Wrongly shaped stored studio data falls back to the base record and is never written back.
  - `cleanOverlay(body)`: the one validation every studio edit passes. `sanitizeStoredOverlay` applies the same check to data read back from the store, and the value sets it checks against (`AVAILABILITY`, `LIFECYCLE`, `PUBLISH`, `UNITS`, `PRICE_VISIBILITY`, `PRICE_CURRENCY`) are exported, the sets as read-only. `createStudioAuth` refuses duplicate role ids.
  - `loginHandler` and `workHandler`: the studio routes; a site's route file wires them up in a few lines. A work edit whose body is JSON but not an object answers 400. If the store fails, the handlers answer 503 "The store did not accept that." `workHandler` takes an optional `onError(error, { method, slug })`, called before that 503 so a site can report the failure; a throwing `onError` never changes the answer.
- The `"web-kit": { "artist": { "enabled": true } }` flag in a site's `package.json` is reserved for phase-2 tooling (`web-kit artist init` and an audit check). Nothing reads it yet, and the export works without it. Shows, the press kit, the payments adapter and `web-kit artist init` follow in the next release.

## 0.9.2
- **Biome preset: `a11y/noRedundantRoles` is now off.** Safari/VoiceOver drops list semantics from a `<ul>`/`<ol>` outside `<nav>` once `list-style: none` or `display: flex|grid` removes its markers, and `role="list"` is the documented way to restore them (Modern Web Guidance, `accessibility` guide). The rule has no options and its fix is automatic, so it flagged that attribute as an error and `biome check --write` silently deleted it, leaving no way to ship the fix without a per-list suppression comment across roughly 380 styled lists. What the rule still caught (`<nav role="navigation">` and the like) is redundant but harmless; losing the list fix is not. Sites pick this up on their next web-kit ref bump; sites with their own standalone `biome.json` need the same one-line setting.
- **`brand-pack` scaffold a11y/perf polish** (affects newly scaffolded boards only; existing client files are theirs). `CopyButton` mirrors its outcome into a visually hidden `role="status"` region so screen readers hear "Copied"; the share board lazy-loads every preview below the first variant (35 images on one page); the board page uses `100dvh` instead of `100vh`; board headings use `text-wrap: balance`.
- **Token contract declares `color-scheme: dark` under `.dark`**, so scrollbars, form controls and the page canvas go dark with the dark palette instead of staying light. `:root` deliberately declares nothing: an author `color-scheme` on the root would override a site's `<meta name="color-scheme">` / Next `viewport.colorScheme` (xenia-network's dark :root palette relies on that), and `light dark` would put dark controls on the light palette since the tokens only flip via `.dark`. No token values changed; a site that already sets `color-scheme` later in the cascade or inline (next-themes) keeps winning.
- Dependency maintenance since 0.9.1: non-major group, node-html-parser 9 (runtime), TypeScript 7 (dev), and security overrides for esbuild/vite/qs.

## 0.9.1
- **`brand-pack` scaffold now lands green in a strict repo.** Running `brand-pack init` in the starter put 14 TypeScript errors and 9 Biome errors into the tree before anyone had written a line: `types.d.ts` declared five of the module's fifteen exports, so `PLATFORMS`, `SHARE_CARD_VARIANTS`, `SIGNATURE_VARIANTS`, `renderSignature`, `renderShareCard`, `CARD_SIZE` and the id lists all resolved to nothing; the emitted `styles.ts`, `CopyButton.tsx` and card route shipped untyped parameters; and the emitted TSX concatenated strings and suppressed two rules in a form Biome ignores. The declarations are now complete (`BrandPackVariant`, `BrandPackPlatform`, `ShareCardNode` added), and every emitted file is the exact text a strict-mode, Biome-checked repo accepts.
- **An unfilled mark no longer takes the client's build down.** `markUrl: "__UNFILLED__"` reached satori as an image source, which is not a broken image but a hard failure: `next build` died on `Image source must be an absolute URL: __UNFILLED__` for four of the five cards. That is the state every client repo is in between `brand-pack init` and the client sending their mark over. Both renderers now show a visible unfilled state where the mark goes, in the card tree and in table-safe email HTML, so the board keeps doing its job of showing what is missing. `photoUrl` is held to the same test, so a sentinel there falls back like a missing photograph rather than crashing.
- **`isUnfilled`** is a new export, and the shared sentinel test moved to `brand-pack/unfilled.mjs` so the renderers can use it without importing the config module that imports them.
- The scaffolded `opengraph-image.tsx` falls back to `type-only` when no card has been picked, rather than throwing on a null variant.

  "web-kit": { "brandPack": { "skip": true, "reason": "...", "date": "2026-09-01" } }

  A bare `skip: true` is itself an error, because that is how a gate quietly stops meaning anything.
